# Translator for Developers

[![test](https://github.com/Xodls128/TranslatorForDevelopers/actions/workflows/test.yml/badge.svg)](https://github.com/Xodls128/TranslatorForDevelopers/actions/workflows/test.yml)

개발 용어와 코드는 영어 그대로 두고, **드래그한 영어 문장만** 한국어로 번역하는 Chrome 확장 프로그램입니다.
번역은 Chrome 내장 Translator API(기기 내 번역)로 처리하므로 외부 서버, API 키, 비용이 없습니다.

## 사용법

| 동작 | 결과 |
|---|---|
| 번역되지 않은 영어를 드래그 | 마우스를 놓은 자리 옆에 `번역` 버튼 표시 → 누르면 드래그가 걸친 문장들을 번역 |
| 번역된 문장(옅은 노란 배경)을 클릭 | 그 문장이 원문으로 전환 (더블클릭 단어 선택과 구분하려고 0.3초 뒤에 바뀜) |
| 원문으로 전환된 문장을 클릭 | 다시 번역문으로 (재번역 없이) |
| 번역된 문장들을 드래그 | 마우스 옆에 `원문 보기` 버튼 표시 → 누르면 걸친 문장들이 모두 원문으로. 누르지 않으면 그냥 선택이라 복사할 수 있음 |
| 번역된 문장을 더블클릭 | 바뀌지 않음 (단어 선택) |
| 번역/원문 문장에 마우스를 올림 | 문장 범위가 옅은 테두리로 표시 |
| 번역문 속 점선 밑줄 용어를 클릭 | `프로그래밍언어 <용어>` 검색 결과를 새 탭으로 열기 |
| 코드 블록 **안에서만** 드래그 | 드래그한 줄의 주석(`//`, `#`, `/* */`, `<!-- -->` 등)만 번역. 코드는 그대로이고 줄 수도 유지. 문단과 같이 드래그하면 코드 블록은 건드리지 않음 |
| **Shift**를 단독으로 0.3초 이상 누르고 있기 | 그동안 페이지의 진짜 원본을 보여 줌 (툴팁·팝업 등 페이지 기능 사용 가능). 떼면 번역본. 대문자 입력·Shift+방향키·Shift+클릭과 겹치지 않도록, 다른 키나 마우스를 누르면 바로 끝나고 입력창에 커서가 있을 때는 동작하지 않음 |
| 번역된 문단의 입력창(흐리게 표시)을 클릭 | 그 문단만 원본으로 바꿔 원본 입력창에 입력. 문단 밖을 누르면 번역본으로 돌아옴 |

- 번역 중 알림의 `취소`로 언제든 멈출 수 있고, 그 전에 끝난 문장은 그대로 남습니다.
  번역 중에도 이미 번역된 문장의 원문 전환(클릭)과 용어 검색은 됩니다.
- 번역이 멈추거나 실패하면 상태를 초기화하고, 원인과 해결 방법을 안내 카드로 보여 줍니다.
  (다운로드 30초 무진행, 문장당 20초 초과, 미지원 브라우저, 오프라인, 권한 거부 등. 원인을 확정할 수 없는 경우는 추정이라고 밝힙니다)
- 코드(`<code>`, `<pre>`, `<kbd>` …)와 태그 없이 섞인 코드 조각(`useState()`, `max_retries`, `config.yaml`, `--save-dev` …)은 번역하지 않습니다.
  로우레벨·하드웨어 문서의 16진수(`0xFF`), 비트 범위(`[31:16]`), 단위 수치(`3.3V`, `16 mA`), 부품명(`ESP32-C6`), 오류 코드(`-EINVAL`)도 그대로 둡니다.
- 제목(`<h1>`~`<h6>`, `role="heading"`)은 영어 그대로 둡니다. 짧고 맥락이 없어 번역 품질이 낮고, 대부분 용어 위주라 영어로도 읽기 쉽기 때문입니다.
  섹션 전체를 드래그하면 본문만 번역되고, 제목만 드래그하면 번역 버튼 대신 안내가 뜹니다.
- 공식 문서 사이트에서는 그 분야 용어 묶음을 함께 씁니다. 예를 들어 docs.espressif.com에서는 `register`, `interrupt`를, docs.kernel.org에서는 `kmalloc`, `spinlock`을 영어로 남기고, 용어를 클릭하면 `ESP-IDF에서 register이란`처럼 문서 맥락을 붙여 검색합니다.
  묶음은 웹 / 백엔드·인프라 / 시스템 / 임베디드·하드웨어 네 가지이고, 사이트 목록은 `src/data/sites.js`에 있습니다.
- 개발 용어는 영어로 남기고 뒤 조사는 `closure은(는)`처럼 병기합니다.
- 번역은 문장이 끝나는 대로 하나씩 화면에 반영됩니다. 대기 중인 문장은 원문 아래 옅은 점선 밑줄로 표시됩니다.
- 번역 결과는 이 기기의 확장 전용 저장소(`chrome.storage.local`)에 저장되어, 같은 문장은 다른 사이트나 다음 방문에도 번역기를 다시 부르지 않습니다.
  웹사이트는 이 저장소를 읽을 수 없고, 외부로 전송되지 않습니다. 8MB를 넘으면 오래 안 쓴 번역부터 지웁니다.
- 문서가 공식 한국어판 링크(`<link rel="alternate" hreflang="ko">`, 언어 메뉴의 같은 사이트 "한국어" 링크 등)를 밝혀 두었으면, 그 페이지에서 처음 번역할 때 결과 알림에 한국어판 링크를 함께 보여 줍니다.
  주소를 추측하지 않고 페이지가 밝힌 링크만 씁니다.
- 옵션 페이지에서 보존할 용어 추가/제외, 검색 엔진(Google/Naver/DuckDuckGo), 분야 용어 묶음(사이트에 맞춰 자동 / 항상 켤 묶음), 공식 한국어판 안내, 번역 결과 저장 켜기/끄기와 지우기를 설정할 수 있습니다.

## 번역기 진단

옵션 페이지의 **번역기 진단 열기**로 이 기기의 내장 번역기를 점검할 수 있습니다.
예문 약 40개를 실제 확장과 같은 과정(용어 감지 → 토큰 보호 → 번역 → 복원)으로 번역해 다음을 보여 줍니다.

- 개발 용어 보호 토큰(`⟦0⟧`)이 그대로 돌아온 비율, 번역기 생성 시간, 문장당 번역 시간
- 실험: 토큰 모양을 `[[0]]`, `{0}`로 바꿨을 때의 보존율, 3문장씩 묶어 번역했을 때의 결과와 시간
- 예문별 원문·번역 결과 (결과 복사 버튼으로 텍스트로 복사)

번역은 기기 안에서만 이루어지고, 마지막 결과는 이 기기에만 저장됩니다.

## 설치 (개발 모드)

1. 데스크톱 Chrome 138 이상을 준비합니다.
2. `chrome://extensions` → 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 저장소 폴더 선택
4. 처음 번역할 때 영어→한국어 언어팩을 내려받습니다. (진행률이 우측 하단에 표시됨)

## 동작 방식

```
드래그 (Selection Range)
  → 선택 영역을 감싸는 블록 요소를 찾는다
  → 블록 아래 인라인 내용을 평평한 텍스트(run)로 펼친다          src/content/text-model.js
      · 글자마다 원래 DOM 위치(텍스트 노드+오프셋)를 기억
      · <code>, <a> 등은 한 글자(U+E000~)로 표시, <pre>/블록 경계는 run을 끊음
      · <br>과 줄바꿈은 공백 (한 문장은 줄바꿈으로 나뉘지 않음)
  → 문장 분할 (Intl.Segmenter + 약어 보정)                        src/core/sentence-splitter.js
  → 선택 영역이 걸친 문장만 고른다
  → 문장이 속한 문단(<p>, <li> …)을 통째로 복제한 사본을 원본 앞에 두고,
    원본은 숨김 표시(data-tfd-hidden)만 붙인다. 이후 작업은 사본에서 한다     src/content/mirror.js
  → 용어/코드/요소를 ⟦0⟧ 토큰으로 보호                            src/core/term-detector.js, protector.js
  → Translator API로 문장별 번역                                   src/content/translator.js
  → 토큰 복원 + 조사 병기
  → 사본 안 문장의 DOM 조각을 떼어 보관하고 그 자리에
    <span class="tfd-sentence" data-tfd-id="n">번역문</span> 삽입   src/content/sentence-dom.js
전환: data-tfd-id(문장 번호)로 원문 조각과 번역문 조각을 모두 보관하고 span 안의 내용만 맞바꿈
      (data-tfd-state: translated | original)
변화 반영: 페이지(React 등)가 원본 문단을 바꾸면 사본을 새로 만들고 전에 번역한 문장을 다시 번역
           (바뀌지 않은 문장은 캐시). 원본이 지워지면 사본도 지우고, 옮겨지면 사본도 따라 옮김
클릭 전달: 사본의 링크·버튼을 누르면 원본의 같은 요소에 클릭을 전달 (페이지 원래 동작 유지)
```

페이지가 관리하는 원본 문단은 내용을 건드리지 않기 때문에, React 같은 프레임워크가 원본을 바꿔도 충돌하지 않습니다.
사본은 원본의 클래스와 `id`까지 복제해서 같은 CSS가 적용되고, 원본 앞에 있어서 `#id` 앵커 이동도 사본으로 갑니다.
`:last-child` 같은 위치 규칙 때문에 여백이 달라지지 않도록, 원본에 실제 적용되던 위아래 여백을 사본에 그대로 지정합니다.
원본은 `data-tfd-hidden` 규칙과 요소에 직접 쓴 `display: none !important`로 숨기고, 그래도 보이면 그 문단은 번역하지 않습니다.
입력창(`input`, `textarea`, `select`)이 있는 문단은 사본의 입력창을 막아 두고, 누르면 원본 문단에서 입력하게 합니다.
동영상·캔버스·iframe처럼 복제하면 내용이 비는 요소가 있는 문단은 번역하지 않고 알려 줍니다.

## 디렉터리

```
manifest.json
src/
  core/        DOM과 무관한 순수 로직 (Node 테스트 가능)
  content/     content script (DOM, UI, Translator API)
  data/        개발 용어 사전과 분야 묶음, 공식 문서 사이트 목록
  options/     옵션 페이지
test/
  *.test.js    단위 테스트 (문장 분할 회귀 세트 포함)
  e2e/         Chromium에서 드래그→번역→복원 흐름 테스트 (가짜 번역기 사용)
```

```bash

npm install       # 처음 한 번: 테스트용 개발 의존성 (Playwright, React. 확장 프로그램 자체에는 포함되지 않음)

npm run test:e2e:chrome  # 설치된 Google Chrome으로 브라우저 테스트
```

## 알려진 한계 / 다음 단계

- **토큰 보존 검증 필요**: 실제 Chrome Translator API가 `⟦0⟧` 토큰을 얼마나 잘 보존하는지는 아직 실측하지 않았습니다.
  토큰이 사라지거나 중복되면 그 문장은 원문으로 두고 알림에 실패 개수를 표시합니다.
- **링크(`<a>`)는 "한국어[원문]"으로 병기**: 링크 글자만 따로 번역해서 링크 기능은 유지합니다.
  API 이름·코드 링크(`Promise`, `useState()`)와 `<code>`를 품은 링크는 영어 그대로, 6단어를 넘는 링크는 병기 대신 원문 툴팁을 답니다.
  링크 글자는 문장과 따로 번역되므로 앞뒤 문맥은 반영되지 않습니다.
- **강조(`<strong>`, `<em>` 등)는 확실한 경우만 유지**: 문장 전체가 강조이거나, 강조 안이 용어·코드 하나뿐이면 번역문에도 강조가 남습니다.
  문장 일부의 일반 단어 강조는 번역 후 위치를 알 수 없어 빠집니다. 원문 보기에서는 그대로입니다.
- **다의어 용어**: `union`, `class` 같은 단어는 문장 중간 대문자형 / 제목형 문장(제목 태그가 아닌 표 머리글 등) / 뒤에 `type`·`keyword` 등 단서가 올 때만 보존합니다.
  일반 문장의 첫 단어로 오면 번역될 수 있습니다.
- **경고 상자 라벨**: Note·Warning·See also 같은 라벨(`.admonition-title` 등 문서 도구별 라벨 요소)은 사이트가 본문과 같은 줄에 표시해도 본문과 따로 번역합니다.
- **코드 주석 번역**: 하이라이터가 표시한 주석을 우선 쓰고, 표시가 없으면 언어에 맞는 주석 기호로 찾습니다. 셸·콘솔 블록은 `#`이 프롬프트일 수 있어 하이라이터가 표시한 주석만 번역합니다.
  이어지는 주석 줄은 한 문장으로 번역해 원래 줄 수에 맞춰 나눠 넣습니다. 사이트의 복사 버튼은 원본 코드를 복사하지만, 코드 블록을 직접 드래그해 복사하면 번역된 주석이 함께 복사됩니다.
  MDN처럼 코드 블록을 웹 컴포넌트(열린 Shadow DOM) 안에 그리는 사이트에서도 동작합니다. 웹 컴포넌트 안의 일반 문단과 닫힌 Shadow DOM은 지원하지 않습니다. Python 문서 문자열(`"""…"""`)은 번역하지 않습니다.
- **문단 사본의 한계**: 사본 안에서는 페이지가 자바스크립트로 붙인 마우스 올림 효과(툴팁·팝업 등)가 동작하지 않습니다.
  클릭은 원본으로 전달되고, Shift를 누르고 있으면 원본의 기능을 그대로 쓸 수 있습니다.
  `id`가 원본과 사본에 중복으로 생깁니다(앵커 이동과 `#id` CSS는 앞에 있는 사본에 적용되어 정상 동작). 사본의 위아래 여백은 원본 위치 기준으로 맞추고, 창 크기가 바뀌거나 사본을 다시 만들 때 다시 맞춥니다.
- **분야 묶음은 초기 선별본**: 실제 번역기로 확인하기 전이라, 공식 문서 점검에서 과잉 보존·누락 사례를 보고 다듬어야 합니다.
